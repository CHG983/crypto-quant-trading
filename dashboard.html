4 · 方法、參數與資料揭露

自動更新架構（與前一版的差異）

前一版：build_dashboard.py 先跑 Python 抓資料、算好一切， 把結果用 const DATA = {...} 內嵌進 HTML。頁面內容是產生當下的快照， 重新整理也不會變，除非重新產生整份 HTML。

本版：HTML 內嵌一段完整的策略引擎（live_engine.js）， 在瀏覽器端用 fetch() 直接呼叫幣安 /api/v3/klines 與 /api/v3/ticker/24hr，取得 K 線後即時重算 EMA / RSI / MACD / ATR / Supertrend 與訊號、強度、停損停利。每 30 秒（可調）自動重算一次，並顯示最後更新時間與倒數。

CORS：data-api.binance.vision 回應 access-control-allow-origin: *，因此不需要任何代理即可直連。 若您的環境（公司網路、代理、地區限制）擋掉跨域請求，頁面會顯示明確錯誤， 可改用隨附的 serve_proxy.py 本機代理模式（見下方說明）。

策略邏輯（CTMA，與 Python 端逐值一致）

趨勢：EMA 21/55 交叉；動能：RSI(14) 站中軸同側 + MACD 柱方向一致； 波動度：ATR(14) 用於停損距離與 ATR% 過濾；風控：3×ATR 初始停損、5×ATR 移動停損、選用 6×ATR 停利。

做多進場：EMA 快線上穿慢線 且 RSI>50 且 MACD 柱>0 且 ATR%≥門檻； 做空進場：EMA 快線下穿慢線 且 RSI<50 且 MACD 柱<0 且 ATR%≥門檻； 出場：反向交叉 或 ATR 停損／移動停損／停利。

訊號強度計分（0–100）

分數 = 100 × ( 0.35×趨勢 + 0.30×動能 + 0.20×波動健康度 + 0.15×Supertrend 一致性 )

趨勢以 ATR 正規化（(EMA快−EMA慢)/ATR / 1.5），使不同波動度的幣種可互相比較； 動能取 RSI 距中軸與 MACD 柱的平均，方向須與趨勢一致；波動健康度在 ATR% 落於 min_atr_pct～8% 時最高分，過低視為盤整、過高視為狂野。

這是啟發式排序分數，不是機率，也未經校準。用途僅在於把「哪些標的訊號較乾淨」 排出先後，不可當成勝率估計。

假資料防護：如何確認頁面數字是真的

1. 頁面上顯示「最後更新」時間與「資料時間戳」，每次刷新都會變。

2. 開啟瀏覽器 DevTools → Network，可看到對 data-api.binance.vision/api/v3/klines?symbol=BTCUSDT&interval=1d 的實際請求與回應。

3. 網頁沒有任何寫死的價格數字；所有數值都由 CTMA.analyzeBars() 依當下抓到的 K 線算出。

4. 抓取失敗時，區塊會顯示錯誤訊息而非舊數字，不會用前一次的資料冒充即時值。

5. 點「立即刷新」後，「最後更新」時間戳每次都會變；K 棒收盤 / 資料延遲欄位也會跟著當下時間重算。 但請注意：已收盤日線的收盤價在同一交易日內不會變（那是已定案的歷史值）， 因此卡片上的「價格」在盤中重複刷新可能相同 —— 這是正確行為，不是快取。 真正逐次變動的是未收盤 K 棒的即時市價與各項時間欄位。
